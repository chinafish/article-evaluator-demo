## 1. 产品概述

### 1.1 产品定位

**认知智能体**（Article Evaluator）是一款面向企业决策者的 AI 驱动文章可信度评估工具。它能够自动解析网页文章，通过 GICS 行业分类体系识别文章所属行业，结合行业基准数据进行深度事实核查和认知盲区分析，最终输出结构化的可信度评估报告。

### 1.2 目标用户

| 用户角色        | 使用场景                   | 核心诉求                               |
| --------------- | -------------------------- | -------------------------------------- |
| 企业高管/决策者 | 阅读行业研报、竞品分析文章 | 快速判断文章可信度，避免被错误信息误导 |
| 战略/投资人员   | 调研行业趋势、评估投资机会 | 核查文章中的数据准确性，发现认知盲区   |
| 产品/市场人员   | 关注行业动态、竞品动向     | 高效筛选高价值信息，获取战略建议       |

### 1.3 核心价值

1. **事实核查** — 对文章中的数据声明进行量化验证（偏差百分比计算）
2. **认知盲区检测** — 识别文章遗漏的关键维度和潜在认知误区
3. **行业基准对比** — 基于何志毅企业图谱（163 个 GICS 四级行业）提供精准数据基准
4. **智能溯源** — 点击角标可跳转到原文高亮段落，支持交叉验证

### 1.4 技术栈

| 层级     | 技术选型                                          |
| -------- | ------------------------------------------------- |
| 后端     | Node.js + Express.js                              |
| 前端     | 原生 HTML/CSS/JavaScript (无框架)                 |
| AI 模型  | 通义千问 qwen3.5-flash / qwen3.5-plus、Kimi k2    |
| 文章解析 | Axios + Mozilla Readability + Puppeteer (Stealth) |
| 实时通信 | Server-Sent Events (SSE)                          |
| 行业数据 | 何志毅企业图谱 (清华产业研究院)                   |

## 3. 功能需求

### 3.1 文章评估（前台）

#### 3.1.1 输入方式

| 输入方式 | 格式要求            | 限制             |
| -------- | ------------------- | ---------------- |
| URL 链接 | 标准 HTTP/HTTPS URL | 自动解析         |
| 文章内容 | 纯文本              | 50 - 10,000 字符 |

- 提供 4 个 URL 示例链接（SaaS、光伏、半导体、春节消费）
- 提供 3 个内容示例按钮（SaaS 增长策略、春节电影、健康饮食）

#### 3.1.2 文章解析（三级策略）

| 级别    | 方式                        | 适用场景           | 特殊处理                                      |
| ------- | --------------------------- | ------------------ | --------------------------------------------- |
| Level 1 | Axios + Mozilla Readability | 大多数公开网页     | 微信公众号 `#js_content` 选择器               |
| Level 2 | Puppeteer + Stealth 插件    | 需要 JS 渲染的页面 | 知乎、豆瓣、金蝶社区（特定选择器 + 模拟滚动） |
| Level 3 | 降级提示                    | 前两级均失败       | 提示用户手动复制内容                          |

**反爬措施（Level 2）**:

- User-Agent 伪装
- WebDriver 属性隐藏
- Navigator permissions 欺骗
- 模拟人类滚动行为
- 浏览器优先级：Playwright Chromium → Chrome → Edge → 内置 Chromium

#### 3.1.3 评估流程

```
用户提交 → 文章解析 → GICS 行业分类 → 智能路由 → AI 评估 → 结果渲染
           (0-10%)    (10-30%)        (后台)      (30-80%)    (85-100%)
```

**Step 1: GICS 行业分类**

- 模型：qwen3.5-flash（快速/低成本）
- 输入：文章标题 + 前 2000 字
- 输出：GICS 四级分类（gics1/gics2/gics3/gics4）+ 置信度 + 理由
- 覆盖范围：163 个 GICS 四级行业分类

**Step 2: 智能路由决策**

系统根据三个条件做出路由判断：

| 条件                 | 检查方式                                                |
| -------------------- | ------------------------------------------------------- |
| 行业基准数据是否存在 | `benchmarkData.getByGics4(gics4)`                       |
| 缓存基准是否存在     | `industryBenchmarkGenerator.loadCachedBenchmark(gics4)` |
| 文章与行业是否相关   | AI 判断（qwen3.5-flash）                                |

三种路由结果：

| 路由                                  | 条件                               | 处理                              |
| ------------------------------------- | ---------------------------------- | --------------------------------- |
| `INDUSTRY_BENCHMARK_READY`            | 有缓存基准 + 文章相关              | 使用行业基准评估                  |
| `INDUSTRY_BENCHMARK_NEEDS_GENERATION` | 有企业图谱数据 + 无缓存 + 文章相关 | 提示用户选择：生成基准 / 使用通用 |
| `GENERAL_BENCHMARK`                   | 无数据或文章不相关                 | 使用通用基准评估                  |

**Step 3: AI 评估分析**

- 模型：qwen3.5-plus（高能力）
- 温度：0.7，最大 Token：4000
- 行业评估：注入企业图谱数据 + 行业研究报告 + 评估基准
- 通用评估：根据文章类型（财经分析/行业研究/产品技术/综合）动态调整

**Step 4: 战略建议生成**

- 嵌入在评估输出中
- 行动建议（30 字以内）
- 决策优先级（高/中/低，基于结论推导）
- 紧急度（基于时效性评估）

#### 3.1.4 评估结果（Block 0/1/2/3 结构）

**Block 0: 总体判断**

- 内容标签（蓝色药丸标签，如 "SaaS"、"AI"）
- 可信度结论（4 级色彩编码）：

| 级别 | 显示文字   | 颜色           |
| ---- | ---------- | -------------- |
| 1    | 可以采信   | 绿色 `#059669` |
| 2    | 基本可信   | 蓝色 `#2563eb` |
| 3    | 谨慎采信   | 黄色 `#d97706` |
| 4    | 不建议采信 | 红色 `#dc2626` |

- 一句话摘要
- 行动建议卡片
- 四张摘要卡片（事实核查数、逻辑核查数、盲点提醒数、时效性）
- 评估方法论说明

**Block 1: 核查详情**

- 数据核查清单：
  - 核查状态图标
  - 声明内容 → 解释说明
  - 数据来源链接 + Tier 等级标签（T1-T5）
  - 角标溯源链接 `[1]` `[2]` 等
  - 行业评估模式：计算量化偏差（如 "基准 6276 亿，文章称 6000 亿，偏差 -4.4%"）
- 逻辑核查清单：类似结构，侧重推理链条验证

**Block 2: 认知盲区**

- 盲区标题 + 描述
- 影响程度（高/中/低，色彩编码）
- 建议与方法
- 类型标注（遗漏/误区）

**Block 3: 评估依据**

- 可折叠面板（默认收起）
- 行业评估模式：
  - 行业概述（发展阶段、关键数据表、竞争格局、产业链）
  - 企业图谱数据（全球冠军企业、关键指标）
  - 行业研究报告摘要（9 大维度）
- 通用评估模式：
  - 评估视角说明
  - 通用基准解释

#### 3.1.5 溯源系统

- 角标引用 `[1]` `[2]` 贯穿 Block 1 和 Block 2
- 点击角标：
  1. 打开原文面板（右侧，默认收起）
  2. 提取引用关键词（中文 2 字以上 + 英文单词 2 字以上）
  3. 模糊匹配原文段落
  4. 高亮匹配段落（黄色背景 `#fef08a` + 黄色标记 `#fbbf24`）
  5. 平滑滚动到高亮位置
- 原文面板：伪浏览器 UI（macOS 窗口控件、地址栏），支持 iframe 代理加载和纯文本降级

#### 3.1.6 SSE 流式进度

实时进度推送，替代传统"黑屏等待"：

| 进度 | 步骤      | 前端提示                                    |
| ---- | --------- | ------------------------------------------- |
| 0%   | 准备      | 准备评估...                                 |
| 5%   | 解析文章  | 正在解析文章...                             |
| 10%  | 解析完成  | 文章解析完成                                |
| 15%  | GICS 分类 | GICS 行业分类中... (正在分析 163 个行业)    |
| 30%  | 分类完成  | GICS 分类完成                               |
| 35%  | AI 评估   | AI 评估分析中... (这是最大头的步骤，请稍候) |
| 50%  | AI 评估中 | AI 评估分析中... (已完成一半)               |
| 80%  | 评估完成  | AI 评估完成                                 |
| 85%  | 战略建议  | 正在生成战略建议...                         |
| 100% | 全部完成  | 评估完成                                    |

- 超时保护：3 分钟自动终止
- 错误处理：友好提示 + 重试按钮
- 正常关闭不触发错误提示（`isComplete` 标志区分）

#### 3.1.7 路由决策交互

当置信度 < 0.7 或需要生成基准时，前端展示路由决策面板：

- 选项 A：「生成行业认知基准」— 触发基准生成流程
- 选项 B：「使用通用认知基准」— 直接用通用基准评估
- 基准生成时展示 3 步进度指示器

### 3.2 管理后台

#### 3.2.1 概览仪表盘

三张统计卡片：

- 已生成基准数量
- 覆盖行业数量
- 基准文件总大小（KB/MB 格式化）

#### 3.2.2 基准列表

网格卡片布局，每张卡片显示：

- GICS 四级行业名称
- 文件大小、生成日期
- 标签：「包含研究报告」（蓝色）、「已缓存」（绿色）
- 点击打开详情弹窗

#### 3.2.3 基准详情弹窗

**双标签页**：

**标签 1：评估基准**

- 基本信息：GICS4 分类、生成时间、是否含报告
- 评估维度：
  - 事实准确性（关键数据点 + 基准值）
  - 行业洞察（必备知识 + 进阶概念）

**标签 2：行业研究报告**（9 大维度，何志毅四步式范式）

1. 执行摘要
2. 行业概述（名称、定义、市场规模、增长趋势、发展阶段、全球定位）
3. 产业链（上游/中游/下游：关键环节、特征、代表企业）
4. 竞争格局（市场集中度、竞争模式、全球冠军分析、中国企业）
5. 发展趋势（技术/商业模式/市场趋势/政策影响）
6. 关键挑战（领域、影响程度、描述）
7. 机遇分析（领域、潜力、描述）
8. 成功要素（关键成功因素、竞争优势）
9. 投资洞察（吸引力、投资论点、关键指标、风险因素、关注重点）

**操作按钮**：

- 「重新生成研究报告与基准」— 三步进度指示器
- 「删除基准」— 二次确认

#### 3.3.1 模型配置

| 任务类型       | 模型          | 参数                      |
| -------------- | ------------- | ------------------------- |
| GICS 行业分类  | qwen3.5-flash | temp=0.3, maxTokens=500   |
| 文章相关性检查 | qwen3.5-flash | temp=0.3, maxTokens=300   |

- `MODEL_ROUTING_ENABLED=true`：启用智能路由
- `MODEL_ROUTING_ENABLED=false`：所有任务使用 Kimi

**何志毅企业图谱**（清华产业研究院）：

- 覆盖 163 个 GICS 四级行业分类
- 每个行业包含：全球 Top 10 + 中国 Top 4 企业
- 核心指标：市值、营收、利润、净资产、研发支出、利润率、ROE、研发强度

#### 3.4.2 缓存策略

| 数据类型     | 缓存位置                       | 过期时间 |
| ------------ | ------------------------------ | -------- |
| 行业研究报告 | `cache/industry_reports/`      | 7 天     |
| 行业评估基准 | `cache/industry_benchmarks/`   | 30 天    |
| 通用基准     | `cache/general_benchmark.json` | 永久     |

#### 3.4.3 基准生成管线

```
企业图谱数据加载
    → 金融数据补全 (stock-metric-query Python 脚本)
    → 基准统计计算 (均值/最大/最小/中位数)
    → 网络搜索补充 (Tavily API，3 级降级)
    → 何志毅研究范式 Prompt 构建 (定位→解构→诊断→展望)
    → AI 生成行业研究报告 (qwen3.5-plus, 12000 tokens)
    → AI 生成评估基准 (qwen3.5-plus, 6000 tokens)
    → 缓存保存
```

## 4. API 接口文档

### 4.1 评估接口

#### POST /api/evaluate

传统 REST 评估接口（非流式）。

**请求体**：

```json
{
  "type": "url",
  "data": "https://example.com/article"
}
```

或

```json
{
  "type": "content",
  "data": "文章正文内容..."
}
```

**成功响应**：

```json
{
  "success": true,
  "article": { "title": "...", "content": "...", "source": "...", "url": "..." },
  "gics": { "gics1": "...", "gics2": "...", "gics3": "...", "gics4": "...", "confidence": 0.95 },
  "evaluation": {
    "block0": { "content_tags": [], "verdict": "...", "summary": "..." },
    "block1": { "data_checks": [], "logic_checks": [] },
    "block2": { "blind_spots": [] },
    "block3": { "industry_overview": {} },
    "decision_priority": "high",
    "relevance_score": 8,
    "urgency_level": "medium"
  }
}
```

**路由决策响应**（需要用户选择时）：

```json
{
  "success": true,
  "requires_user_action": true,
  "task_id": "uuid",
  "route_decision": {
    "gics4": "应用软件",
    "confidence": 0.65,
    "options": [
      { "id": "generate_benchmark", "label": "生成行业认知基准" },
      { "id": "use_general", "label": "使用通用认知基准" }
    ]
  }
}
```

#### POST /api/evaluate/choose-option

用户选择路由方案。

**请求体**：

```json
{
  "task_id": "uuid",
  "option": "generate_benchmark"
}
```

#### GET /api/evaluate-stream

SSE 流式评估接口。

**参数**（Query String）：

- `url` — 文章 URL
- `content` — 文章内容（与 URL 二选一）

**SSE 事件格式**：

```
data: {"step": "parsing", "progress": 10, "message": "文章解析完成", "data": {}}
data: {"step": "gics", "progress": 30, "message": "GICS 分类完成", "data": {"gics4": "应用软件"}}
data: {"step": "ai-eval", "progress": 80, "message": "AI 评估完成", "data": {}}
data: {"step": "complete", "progress": 100, "message": "评估完成", "data": {"evaluation": {...}}}
```

**超时**：180 秒（3 分钟）

#### GET /api/evaluate/stats

获取模型使用统计。

**响应**：

```json
{
  "total_calls": 150,
  "total_tokens": 85000,
  "models": {
    "qwenFlash": { "calls": 80, "tokens": 15000 },
    "qwenPlus": { "calls": 60, "tokens": 65000 },
    "kimi": { "calls": 10, "tokens": 5000 }
  }
}
```

### 4.2 管理后台接口

#### GET /api/admin/benchmarks

获取所有缓存的行业基准列表。

**响应**：

```json
{
  "success": true,
  "stats": { "total": 6, "industries": 6, "totalSize": 102400 },
  "benchmarks": [
    {
      "filename": "应用软件.json",
      "gics4": "应用软件",
      "size": 18432,
```

#### GET /api/admin/benchmarks/:filename

获取单个基准详情。

#### POST /api/admin/benchmarks/regenerate

重新生成行业基准。

**请求体**：

```json
{ "gics4": "应用软件" }
```

**流程**：生成研究报告 → 生成评估基准 → 缓存保存 → 返回完整基准数据

#### DELETE /api/admin/benchmarks/:filename

删除基准文件。

### 4.3 辅助接口

**参数**：`url` — 目标 URL

返回最新性能报告（当前为桩实现，不可用）。

## 5. 非功能需求

### 5.1 性能指标

| 指标             | 目标值      |
| ---------------- | ----------- |
| SSE 进度更新延迟 | < 100ms     |
| 前端渲染帧率     | 60fps       |
| 内存占用增量     | < 10MB/连接 |
| 并发连接支持     | 最多 10 个  |
| 文章解析超时     | 10 秒       |
| AI 评估超时      | 3 分钟      |

### 5.2 健壮性

- **JSON 解析容错**：4 级降级策略（直接解析 → 代码块提取 → 大括号计数算法 → 正则匹配）
- **模型降级**：qwen3.5-flash/plus 不可用时降级到 Kimi
- **解析降级**：Axios 失败 → Puppeteer → 用户手动输入
- **评估降级**：行业评估失败 → 通用评估

### 5.3 缓存策略

- 行业研究报告：7 天过期，支持模糊匹配查找
- 行业评估基准：30 天过期，支持子串匹配和字符交叉匹配
- 基准匹配算法：精确匹配 → 子串匹配 → 字符交叉模糊匹配
